# ClearChart

A transparent patient and clinician workspace built for a 36-hour hackathon. Go renders every screen and Datastar applies server-sent HTML fragments, so a doctor's new note appears in the patient's timeline and a patient's report appears in the doctor's reports center across open tabs. The application contains no custom frontend JavaScript.

## Run the demo

Install Go 1.23 or newer, then run:

```sh
go mod download
go run .
```

Open [http://127.0.0.1:8080](http://127.0.0.1:8080). With `DATABASE_URL` unset, ClearChart starts with synthetic, in-memory seed data. Changes in this mode disappear when the server stops. Tailwind CSS, Datastar, and web fonts load from CDNs, so the browser needs internet access.

The in-memory demo automatically includes **303 fictional patients**. Dr. Sarah Chen has 302 patients, including the 300 additional patients generated by `bulk_seed.go`. Each additional patient has two notes, one mock prescription, two individually labeled scan illustrations, a mock report filename, and three recovery scores. Names, IDs, and visit references stay consistent across restarts. Restart `go run .` after updating the app to load the larger dataset.

If using the portable Go toolchain prepared in this workspace, run from PowerShell:

```powershell
$env:PATH = "$PWD\.tools\go\bin;$env:PATH"
$env:GOCACHE = "$PWD\.tools\go-cache"
$env:GOMODCACHE = "$PWD\.tools\go-mod-cache"
$env:GOPATH = "$PWD\.tools\go-path"
go mod download
go run .
```

## Connect Supabase

1. Create a Supabase project and open its SQL editor.
2. Execute `schema.sql`, then `seed.sql`. The base seed includes two doctors, three patients, care teams, notes, prescriptions, imaging, uploads, recovery scores, and mock watch readings. To add the same 300 extra patients available in memory mode, execute `seed_large.sql` next. It adds 1,500 records (600 with image references), 300 filename-only uploads, and 900 recovery scores. The script is repeatable and preserves existing rows; it requires the two doctors from `seed.sql`.
3. Copy the project's PostgreSQL direct connection or session-pooler connection string. Use the session pooler if the direct host's IPv6 connection is unavailable. Include `sslmode=require` and URL-encode special characters in the database password.
4. Set the environment variable and start the server:

```powershell
$env:DATABASE_URL = 'postgresql://postgres.PROJECT_REF:PASSWORD@POOLER_HOST:5432/postgres?sslmode=require'
go run .
```

Use the actual connection string from your project's Connect panel; the example above contains placeholders. The application reads process environment variables and does not automatically load `.env` files. `.env.example` documents the available settings. Keep database credentials on the Go server. Tables have row-level security enabled with no browser access policies; the server connection must use a database role authorized to access them.

`HOST` defaults to `127.0.0.1` and `PORT` defaults to `8080`. For a demo host that requires external access, explicitly set `HOST=0.0.0.0`.

## Judge walkthrough

1. Open `/demo/patient` to view Alex Morgan's medical timeline, care team, healing status, report uploads, and plain-language assistance.
2. Open `/demo/doctor` in another tab to view Dr. Sarah Chen's patients, record form, reports center, and mock Apple Watch data.
   Scroll the patient list and select patients near the middle or end, such as Zoe Thompson. Verify that the selected patient's name, five records, healing scores, and two scan references change together. The reports center contains uploads from all linked patients. The 300 additional patients cover six fictional recovery scenarios: knee, shoulder, ankle, wrist, spine, and hip.
3. Add a note, prescription, or imaging record for Alex in the doctor tab. Watch the patient's timeline update without reloading.
4. Submit a report from the patient tab. Its filename appears in both the patient's uploads and the doctor's reports center. Uploads accept a maximum 5 MB; file bytes are discarded and only the filename is saved.
5. Try the doctor and patient onboarding forms to explore role-specific profile fields.

The AI card uses preset or rule-based explanations. Recovery charts are CSS bars, scan images are synthetic demo illustrations, and Apple Watch readings are synthetic. Additional patients' images are served locally at `/mock-scans/{patientID}/1.svg` and `/mock-scans/{patientID}/2.svg`; no image download or external image host is needed. No LLM, wearable connection, or file-storage service is needed.

## Implementation and checks

- Go standard-library `net/http` and `html/template`.
- PostgreSQL through `github.com/lib/pq`, with an in-memory demo fallback.
- Datastar form actions and server-sent events for mutations and live updates.
- Tailwind CSS via CDN, shared styles, and separate patient and doctor templates.

```sh
go test ./...
go vet ./...
```

This is a synthetic-data prototype. Role-scoped cookie sessions demonstrate patient and doctor permissions, but the demo account switcher and onboarding do not verify identity. Use it for the hackathon with fictional data only; it is not a production EHR and must not contain real patient health information.
